# מנתב פניות הציבור: חבילת השקה

צ'אט פתוח שבו הפונה כותב במילים שלו במה מדובר. סורק מילות מפתח מזהה את סוג הפנייה ואת השלב שבו הפונה נמצא, ומפנה אותו לערוץ הנכון: נציבות התאגיד, פורטל הפיקוח על הבנקים, מסלול דחוף, תחום האסדרה או גוף אחר. כשאין בטקסט מספיק מילות מפתח, הפונה מופנה לערוץ הכללי של היחידה לפניות הציבור.

הרכיב סטטי לחלוטין. אין בו שרת, מסד נתונים, קריאות רשת, עוגיות או אחסון, והטקסט שהפונה כותב לא יוצא מהדפדפן.

## תוכן החבילה

| קובץ | תפקיד |
|---|---|
| `index.html` | העמוד עצמו |
| `router.css` | עיצוב. גופן ברירת המחדל הוא Assistant, עם נפילה ל־Arial |
| `router.js` | הסורק, היעדים והממשק. ההגדרות להשקה נמצאות בראש הקובץ (`CONFIG`) |
| `tests/run-tests.js` | בדיקת ניתוב אוטומטית של 22 שיחות לדוגמה |

## אירוח

שלושת הקבצים מועלים כמו שהם לכל שרת אינטרנט. אין שלב בנייה ואין התקנות.

הרכיב צריך להתארח בדומיין רשמי של בנק ישראל, למשל בתיקייה ‎`/information/public-enquiries-unit/router/`‎. אין לארח אותו בדומיין שאינו רשמי, כי עמוד שמציג שירות של בנק ישראל בכתובת אחרת עלול להיתפס כהתחזות.

"מחוץ לארגון" פירושו כאן שאין שום תלות במערכות הפנימיות. ספק האתר יכול לארח את הקבצים בתשתית שלו, כל עוד הכתובת נמצאת תחת הדומיין הרשמי.

## שילוב באתר

**אפשרות 1, מומלצת: עמוד עצמאי וקישור אליו.** בדף "פניות הציבור ובקרה צרכנית", ברשימה "מה ברצונך לעשות?", מוסיפים פריט:

```html
<a href="/information/public-enquiries-unit/router/">לא בטוחים לאן לפנות? כתבו במה מדובר ונפנה אתכם</a>
```

**אפשרות 2: הטמעה בתוך דף קיים.**

```html
<iframe src="/information/public-enquiries-unit/router/"
        title="מנתב פניות הציבור"
        style="width:100%; height:780px; border:0"
        loading="lazy"></iframe>
```

הצ'אט גולל בתוך המסגרת, ושורת הכתיבה נשארת צמודה לתחתית שלה. כל הקישורים ליעדים נפתחים בלשונית חדשה.

## הגדרות לפני השקה

ההגדרות נמצאות בראש `router.js`, באובייקט `CONFIG`:

- **`regulationChannel`**: הערוץ הייעודי של היחידה לאסדרה צרכנית לשאלות פרשנות על הוראות ועל האוגדן. כל עוד הערך `null`, שאלות כאלה מקבלות את טופס הפנייה הכללי, עם הנחיה לציין שמדובר בשאלה פרשנית. דוגמה:
  ```js
  regulationChannel: { label: 'פנייה ליחידה לאסדרה צרכנית', href: 'https://www.boi.org.il/...', note: 'זמן מענה: ...' }
  ```
- **`debugHash`**: פתיחת הכתובת עם ‎`#debug`‎ בסופה מציגה מצב בדיקה. במצב הזה רואים את המילים שזוהו מודגשות, את הניקוד לכל סוג פנייה, את המילון המלא ופלט מובנה של כל פנייה. המצב מיועד לבדיקות פנימיות, והמשתמשים הרגילים לא רואים אותו.

## רשימת בדיקות לפני העלאה

1. **פרטי הנציבויות:** אימות טלפונים, דוא"ל וקישורים של 13 הנציבויות מול היחידה (מערך `BANKS` ב־`router.js`). בנובמבר 2026 אומתו מול אתרי הבנקים הטלפונים של בנק יהב (02-5009956) ושל בנק ירושלים (‎*5727, לבירור מצב תלונה בלבד). הטלפון של כאל לא אומת, ולכן הוסר, וכאל מוצגת עם הטופס המקוון בלבד.
2. **ערוץ האסדרה:** הגדרת `regulationChannel`, או החלטה מפורשת להשאיר את הערוץ הכללי.
3. **ניסוחים:** אישור של היחידה לפניות הציבור ושל הדוברות לנוסחי היעדים (אובייקט `N`).
4. **אבטחת מידע:** אין קריאות רשת ואין אחסון. הרכיב עובד עם מדיניות CSP מחמירה (‎`default-src 'self'`‎), כי אין בו סקריפטים, סגנונות או גופנים מבחוץ, ואין סגנונות inline.
5. **נגישות:** בדיקה של רכז הנגישות לפי ת"י 5568 (WCAG 2.0 AA). הרכיב כולל כיוון RTL, תוויות לשדות, ניווט מקלדת, מסגרת פוקוס גלויה, אזור הודעות חי לקוראי מסך וכיבוד של הגדרת "הפחתת תנועה".
6. **בדיקת ניתוב:** הרצה של ‎`node tests/run-tests.js`‎. כל 22 המקרים צריכים לעבור.

## תחזוקת המילון

מילות המפתח נמצאות במערך `LEX` בקובץ `router.js`. כל קבוצה מוסיפה משקל (`w`) לסוג פנייה (`c`), או מסמנת מצב (`f`), למשל דחיפות, הליך משפטי או השלב מול הנציבות.

- התחיליות ו, ה, ב, ל, מ, ש, כ מזוהות אוטומטית: "עמלה" תופסת גם "בעמלה" ו"שהעמלה".
- מילה מזוהה גם כשיש לה סיומת: "עמלה" תופסת גם "עמלות". כדי לזהות מילה שלמה בלבד, מוסיפים `$` בסופה (למשל `'מס$'`, כדי שלא תיתפס "מסלול").
- ביטוי ארוך יותר גובר על קצר יותר. "ביטוח לאומי" נתפס כקריטריון דחיפות, ולכן "לאומי" שבתוכו לא נספר כבנק לאומי.
- סף הניתוב הוא 2. ניקוד נמוך מזה, או טקסט בלי מילות מפתח בכלל, מפנה לערוץ הכללי (מסלול 00).
- שמות התאגידים והכינויים שלהם נמצאים במערך `BANKS`, בשדה `a`.

אחרי כל שינוי מריצים את בדיקת הניתוב. כשמוסיפים מילים, מומלץ להוסיף גם מקרה בדיקה מתאים ל־`CASES` שבקובץ הבדיקה.

## מדידה

הרכיב לא שולח כלום. כדי למדוד את הירידה בניתוב שגוי, אפשר להוסיף אירוע של מערכת האנליטיקס של האתר בכל ניתוב, ובו קוד המסלול בלבד (`routeCode`, למשל `"05"`). את הטקסט שהפונה כתב אין לשלוח לשום מערכת.

## שלב המשך אפשרי: חיבור למערכת ניהול הפניות

בכל ניתוב הרכיב מפיק פלט מובנה, שאפשר לראות במצב הבדיקה:

```json
{
  "inquiryType": "complaint",
  "routeCode": "05",
  "destination": "בירור קצר מול הנציבות, ואז פורטל הפיקוח",
  "corporation": "בנק לאומי",
  "ombudsmanStage": "noans",
  "daysSinceFiled": 60,
  "urgentSignal": false,
  "legalProceeding": false
}
```

ספק המערכת יוכל למפות את השדות האלה לשדות של פנייה ב־Salesforce, למשל כשדות נסתרים בטופס פנייה. חיבור כזה כבר שולח מידע מהדפדפן, ולכן הוא מחייב אישור אבטחת מידע נפרד.
